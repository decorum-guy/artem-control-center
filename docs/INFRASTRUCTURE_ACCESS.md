# Инфраструктура и существующий доступ с Mac

## Назначение и источник сведений

Это единая карта доступа для агентов проекта. Роли трёх SSH alias и изменения доступности `kz-bot` сообщил владелец 24.11.2026. Описания Panel Agent и приватных forwards сверены с документацией репозитория. При подготовке этого документа новые SSH-подключения и аппаратные проверки не выполнялись.

На Mac владельца доступ уже настроен. Не предлагай настройку SSH с нуля, перенос HA или создание нового туннеля до проверки существующего маршрута. Из облачного окружения нельзя предполагать наличие Mac SSH config и ключей. Отсутствие этих данных в облаке не означает отсутствие доступа на Mac.

## Три SSH alias

| Команда с Mac | Узел | Роль | Что проверять по задаче |
| --- | --- | --- | --- |
| `ssh control-panel-pc` | Домашний Samsung, Windows | Постоянный узел панели: kiosk, Panel Agent и локальные исполнители. Через Samsung доступен Android TV по ADB. | Реальные hostname, checkout, runtime SHA, задачи планировщика, процессы, loopback health; локальные интеграции и ТВ. |
| `ssh ha-vps` | VPS со стеком Home Assistant / AliceTG_Bot | HA остаётся на сервере; Samsung обращается к его API через существующие приватные forwards. | Контейнеры, HA, локальный API Planning, состояние существующих соединений и внешних зависимостей. |
| `ssh kz-bot` | Отдельный зарубежный сервер-прокси | Исходящий зарубежный доступ. Подтверждённый владельцем потребитель — Telegram-бот на `ha-vps`, обращающийся к Telegram через этот сервер. | Доступность узла и нужной proxy-службы, только когда это относится к текущему инциденту. |

`kz-bot` — имя SSH alias. По этому имени нельзя определить протокол прокси, его порт, перечень всех потребителей или местоположение HA. Адреса, пользователи, ProxyJump, пути к ключам и фактическая конфигурация берутся из уже настроенной среды; секретные значения в документацию не копируются.

## Доступность kz-bot

**Актуальное сообщение владельца от 24 ноября 2026 года: `kz-bot` восстановлен.** Новая SSH-проверка, проверка proxy-службы и её потребителей при обновлении этой записи не выполнялись.

Ранее в тот же день владелец сообщил о временном отключении до продления сервера. Эта остановка — историческое состояние; прежнее ожидание продления больше не использовать как текущий статус.

- При релевантной диагностике сверяй SSH, нужную proxy-службу и конкретного потребителя. Доступность сервера и успешная работа Telegram-бота — отдельные наблюдения.
- Старую остановку не использовать как объяснение текущего сбоя без проверки соответствующего маршрута.
- Состояние HA, локального Planning API, панели и других сервисов проверяется независимо.
- Сообщение о восстановлении не является поручением менять прокси, переключать YouTube с Happ, переносить потребителей или создавать уведомления.
- Дальнейшие изменения доступности отмечай датой и источником; не превращай разовый статус в постоянный флаг кода.

## Разделение маршрутов

| Путь | Назначение и граница |
| --- | --- |
| Mac → три SSH alias | Административный доступ для разработки и порученной диагностики. |
| Samsung → `ha-vps` | Приватные HA/Planning forwards; документированы Samsung loopback `18123` и `18088`. Это не публичные API через Caddy. |
| Telegram-бот на `ha-vps` → `kz-bot` → Telegram | Подтверждённая владельцем исходящая proxy-зависимость. Других потребителей без inspection не добавлять. |
| Samsung → Станция / BLE-лента | Прямые локальные источники в кандидате PR #372. Наличие кода в PR не доказывает установку в основном runtime. |
| Mac → Samsung → Android TV | ADB, `screencap`, существующий `tv-mirror` / `scrcpy`; [подробный маршрут](TV_ACCESS.md). |
| Внешний TV-пульт → существующий ограниченный вход → Samsung TV Executor | Отдельный маршрут управления ТВ. Его нельзя автоматически приравнивать к `kz-bot` или к приватным HA forwards. |

Mac — инструмент разработки и наблюдения, а не обязательный постоянно включённый участник runtime. Home Assistant на Samsung не переносится.

## Как проверять доступ без лишних действий владельца

1. Установи, в какой среде работаешь: Mac владельца или облачный агент. Прочитай текущие правила и scope задания.
2. На Mac используй существующий alias. Для короткой проверки выбранного узла достаточно ограниченного read-only вызова, например:

   ```bash
   ssh -o BatchMode=yes -o ConnectTimeout=8 -o ConnectionAttempts=1 control-panel-pc hostname
   ```

   Для серверной задачи выбирай соответственно `ha-vps` или `kz-bot`. Не опрашивай все узлы без необходимости. Не отключай проверку host key; неожиданный ключ требует выяснения причины.
3. Разделяй отсутствие локального alias/ключа, ошибку аутентификации, сетевую недоступность и доступный SSH при неработающем приложении. Это разные результаты.
4. После подключения сначала определи реальные пути, платформу и версию. Не применяй старый путь или SHA как текущий без сверки.
5. Выводи только обезличенные health-данные. Для настройки с секретами достаточно `set/missing`; не публикуй `.ssh/config` целиком, приватные ключи, env, cookies или токены.
6. Выполняй самостоятельно доступные команды и получение экранов. Владелец нужен для входа/2FA или физического наблюдения, которое действительно невозможно получить технически.

Подтверждённый доступ используется в пределах уже порученной задачи. Повторное разрешение на каждую read-only проверку не требуется; наличие SSH само по себе не разрешает произвольные изменения production. Общие границы: [RULES.md](../RULES.md).

## Связь с владельцем

Следуй каналу текущего задания. Если работа идёт в чате, продолжай в нём. Если владелец выбрал существующий Telegram-канал, учитывай его реальную доступность и установленный порядок подключения. Не создавай нового бота, уведомления или канал в качестве реакции на недоступный `kz-bot`. Отсутствие Telegram не блокирует независимую работу с репозиторием.
