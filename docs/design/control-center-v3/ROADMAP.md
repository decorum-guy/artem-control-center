## 1. Правила ведения

- Один этап — одна ветка `redesign/v3-stage-<N>` от ветки предыдущего этапа, draft PR с базой
  на предыдущий этап. По последующему решению владельца проверенный код разрешено объединять с `main` и ставить на рабочую панель штатным обновлятором.
- Штатная установка использует V3 по умолчанию по решению владельца от 18.11.2026.
  Профиль `accepted-v2` включает `VITE_V3_VISUAL_SKIN`. Явное значение `false` выбирает V2.
  В dev и fixture V3 включается явным значением `true`.
- В конце каждого этапа обновлять этот файл: что сделано, что проверено, что не проверено,
  что дальше. Если заканчивается время или контекст: закоммитить рабочее состояние, записать
  сюда и остановиться.
- Отчёт по формату `RULES.md`, раздел 6. Отдельно перечислять решения, нужные от владельца.

## 6. Решения, принятые без владельца

1. Копия задания хранится в репозитории как `TASK.md`, чтобы работу можно было продолжить
   с любого компьютера.
2. Скриншоты «до» лежат в `artifacts/redesign-v3/before/` в WebP (качество 80): полный набор
   в git весит 4,1 МБ против 13,4 МБ в PNG. Папка `artifacts/` в .gitignore, поэтому
   файлы добавлены через `git add -f`. Скриншоты следующих этапов складывать так же; для PR
   брать кадры оттуда.
3. Инструменты снимков и запуска лежат в `docs/design/control-center-v3/tools/`. Это
   ревью-инструменты, а не продуктовый код и не тесты.
4. Пожелание владельца из Telegram (17.11, 15:23): «мега красиво, может, жидкое стекло,
   футуристично и элегантно». Принято как ориентир для раздела 3.4. «Жидкое стекло»
   делается без `backdrop-filter`: блик по верхней кромке, градиентная рамка-ободок,
   полупрозрачные слои над неподвижным фоном, мягкая подсветка активных приборов.
   Настоящее размытие допускается только для подложки Sheet в motion-full и только после
   замера на Samsung (этап 7), как требует раздел 3.8.
5. Замена нативных `select` и `range` на свои контролы рендерится только под `skin-v3`.
   Без флага остаются нативные контролы, поэтому существующие e2e проходят без правок
   ожиданий (требование §7). Тесты новых контролов идут в профиль `v3-skin-*`. Это способ
   совместить §4 («вместе с правкой их тестов») и §7. Если владелец хочет заменить контролы
   для всех, это противоречит §7, и нужно его решение.
6. Единый PageHeader внедряется с сохранением DOM-контракта (data-testid, aria, текст,
   порядок фокуса). Различия вида (например, заголовок Календаря справа) выравниваются
   CSS-правилами под `skin-v3`, без перестановки DOM.

7. Стартовые значения токенов, не прошедшие контраст, заменены ближайшими подходящими
   (смешение к белому ночью и к чёрному днём до 4.6:1, `tools/contrast.mjs`). Ночь:
   `text-muted` `#7385a0` → `#8494ab`, `unavailable` `#8e8698` → `#9790a0`. День:
   `text-muted` → `#5b6b83`, `accent` → `#00719c`, `heat` → `#9b5900`, `success` →
   `#0c7853`, `warning` → `#945e00`, `danger` → `#c13148`. Обоснование в DESIGN_SPEC §3–4.
   Обе темы проверены на снимках этапов 1 и 2.
8. RingGauge: задание требует, чтобы кольцо переходило за 400 мс, и одновременно разрешает
   анимировать только `transform` и `opacity`. Заполнение через `stroke-dashoffset` поэтому
   обновляется без перехода, а смена состояния идёт кроссфейдом слоёв по `opacity`
   (DESIGN_SPEC §7.2). Плавное заполнение возможно через поворот двух полуколец под маской,
   но только после замера на Samsung; это вопрос к владельцу (§7, п. 5).
