# Доступ к Android TV с Mac через Samsung

## Происхождение и актуальность

24.11.2026 владелец сообщил о действующем маршруте доступа: Mac подключается по SSH к Samsung, Samsung обращается к Android TV по ADB в домашней сети. Снимки доступны через `screencap`, живое изображение и управление с Mac — через `tv-mirror` на основе `scrcpy`. Веб-пульт отправляет команды сервису на Samsung, а тот передаёт их телевизору по ADB.

Это зафиксированное сообщение владельца, а не новый аппаратный тест автора документа. При использовании агент проверяет фактическую доступность, текущие пути, выбранное устройство и версии. IP, ADB serial, порты, расположение wrapper и секреты в этом документе не задаются.

Общая карта трёх SSH-доступов с Mac — [INFRASTRUCTURE_ACCESS.md](INFRASTRUCTURE_ACCESS.md). Для ТВ основная цепочка проходит через Samsung; зарубежный `kz-bot` не следует автоматически считать её частью.

## Существующие маршруты

| Задача | Маршрут и инструмент |
| --- | --- |
| Диагностика и доступ к устройству | Mac → `ssh control-panel-pc` → существующий ADB-клиент Samsung → подтверждённый Android TV |
| Снимок интерфейса ТВ | `screencap` на выбранном ТВ через существующий ADB-доступ; получение файла на Mac |
| Живое изображение и управление | Существующий `tv-mirror` / `scrcpy` с Mac; параметры транспорта определить по установленному wrapper |
| Пользовательские команды | Веб-пульт или Panel Agent → штатный сервис/TV Executor на Samsung → ADB → ТВ |
| Внешний пульт iPhone | Авторизованный HTTPS-пульт → существующий relay → SSH-туннель Samsung → локальный TV Executor |
| Работа без Mac | Постоянный исполнитель остаётся на Samsung; Mac используется для разработки, наблюдения и проверки |

Через штатный исполнитель уже организованы кнопки пульта, громкость, управление подсветкой и открытие ссылок. Контракты действий и подтверждений описаны в [TV_CONTROL.md](TV_CONTROL.md). Исходники отдельного исполнителя и его документацию искать в [home-tv-control](https://github.com/decorum-guy/home-tv-control); изменение внешнего проекта требует соответствующего разрешения.

## Внешний пульт и датированная приёмка

24.11.2026 владелец подтвердил открытие пульта на домене `tv.myhomeassistantisverybest.art` через мобильную сеть и работу кнопки «Домой» после ремонта туннеля Samsung. Это отдельный вход для пульта, а не публикация всего Panel Agent. По [отчёту кандидата](https://github.com/decorum-guy/artem-control-center/blob/e787ce4a258b8bd09858db44b3192398ec623fa6/docs/plans/SAMSUNG_AUTONOMOUS_RESULTS_2026_11_24.md), VPS получил HTTP 200 от origin Samsung. Автор этой карты повторно к устройствам не подключался.

Исполнитель зафиксировал запуск `%LOCALAPPDATA%\HomeTvControl\domain-origin\start-domain-tunnel.ps1` из каталога владельца отдельной задачей `Home TV Domain Tunnel` от SYSTEM. После выхода SSH launcher делает паузу от 5 до 60 секунд перед следующей попыткой и сбрасывает её после устойчивого соединения. SHA-256 установленного файла по отчёту — `eb9f9ea18251214d6032caf2faffe131bf6ad84a8892cbf1742cd1bf446674a4`. [Исходник на точном коммите home-tv-control](https://github.com/decorum-guy/home-tv-control/blob/ed723c0969445b084a2c2bd72b607e440bc368c0/scripts/windows/start-domain-tunnel.ps1).

При разрешённом обслуживании использовать зарегистрированную задачу: `Start-ScheduledTask -TaskName 'Home TV Domain Tunnel'`. Для отката остановить её командой `Stop-ScheduledTask` с тем же именем, восстановить `start-domain-tunnel.ps1` из `start-domain-tunnel.before-bounded-retry.ps1` в том же каталоге с прежним ACL и снова запустить задачу. Проверить origin на VPS и защищённый пульт. Путь резервной копии и существование задачи сначала сверить. Настройки SSH, HA, relay и TV Executor при таком откате сохраняются. [Порядок восстановления в репозитории исполнителя](https://github.com/decorum-guy/home-tv-control/blob/ed723c0969445b084a2c2bd72b607e440bc368c0/docs/TV_DOMAIN_TUNNEL_RECONNECT.md).

При проблеме пульта с мобильной сети проверяй именно внешний маршрут. Проверка домашнего LAN-адреса с Mac не доказывает доступность публичного входа с iPhone. Успех от 24.11 не является непрерывной гарантией доступности.

При разрешённой установке TV voice из preview основной обработчик сначала остаётся выключенным. После проверки основной панели остановить получателя preview и только затем включить единственный основной обработчик. Дедупликация внутри одного процесса не предотвращает двойную команду от двух процессов. Точный порядок установки и отката — в отчёте кандидата; эта документация сама не разрешает установку.

## Как агенту войти в существующий доступ

1. На Mac определить, чем является `tv-mirror`: executable, script, alias или shell function. Использовать обычный поиск команды и прочитать доступную реализацию/справку без публикации приватных параметров.
2. Из фактической конфигурации wrapper выяснить используемые SSH/ADB-параметры и способ запуска `scrcpy`. Не придумывать прямой маршрут Mac → ТВ и не перестраивать рабочий доступ.
3. Через `ssh control-panel-pc` проверить действующий ADB-клиент, список устройств и статус штатного TV Executor. Если устройств несколько, выбирать подтверждённый телевизор явно.
4. Сопоставить выбранное устройство с настроенным исполнителем. Старый IP или serial из переписки не считать текущим.
5. Получить собственный снимок ТВ через существующий `screencap`-маршрут. Для интерактивного наблюдения использовать `tv-mirror`, если это необходимо для проверки.
6. Для проверки продукта отправлять команды через штатный сервис/адаптер; прямые ADB-наблюдения использовать для независимого подтверждения результата.
7. При отказе одного канала сохранить конкретную ошибку и проверить остальные уже настроенные каналы. Не объявлять весь телевизор недоступным по одной ошибке просмотра.

Наличие доступа позволяет агенту самостоятельно смотреть интерфейс и собирать скриншоты. Не перекладывать эти действия на владельца, когда они доступны исполнителю. Интерактивный вход или физическое наблюдение, которого действительно не хватает, отмечать отдельно; при задании работать без владельца продолжать остальные части и оставить этот пункт для приёмки.

## Какие результаты подтверждают наблюдения

| Наблюдение | Допустимый вывод | Ограничение |
| --- | --- | --- |
| Снимок `screencap` или изображение `scrcpy` | Содержимое интерфейса Android, видимая страница или приложение | Не доказывает свечение физической подсветки |
| Foreground приложения и его интерфейс на снимке | Запуск нужного приложения, например YouTube | Не доказывает воспроизведение ролика |
| Readback штатного исполнителя и доступные сведения Android об экране/подсветке | Конкретное сообщённое устройством состояние экрана | Не подменяет физическое наблюдение, если фактическая подсветка остаётся неопределённой |
| Успех отправки ADB-команды | Команда отправлена без данной ошибки транспорта | Не является достаточным подтверждением результата на устройстве |

Перед проверкой погашенного экрана изучить параметры `tv-mirror`: запуск наблюдения или управляющий ввод могут изменить проверяемое состояние. Сверять состояние до и после подключения наблюдателя. Не будить ТВ перед чтением, которым подтверждается `screen-off`.

Различать погашенный экран при доступном Android/ADB, глубокий сон и отсутствие связи. Успех включения подсветки не доказывает выход из глубокого сна.

## Рабочие границы

- Использовать действующий SSH/ADB-контур. Поиск доступа не требует `adb kill-server`, перепривязки, изменения debugging/network settings или перезапуска штатного исполнителя.
- Управляющие эксперименты выполнять в scope, разрешённом владельцем. Этот документ описывает возможность доступа и сам по себе не выдаёт разрешение на произвольные изменения устройств или production.
- Не выполнять повтор потенциально отправленной физической команды после неопределённого результата без проверки состояния.
- Снимки и записи экрана хранить в локальных материалах проверки; в Git — компактные обезличенные результаты. Не публиковать приватное содержимое экрана, токены, домашние адреса и тяжёлые видео.
- В отчёте указывать, какие соединения реально открывались, каким способом получены изображения, что подтвердил readback и что осталось непроверенным.
- Временный режим «владелец спит, вопросов не задавать» относится к конкретному заданию. Он не меняет правила связи и разрешений для всех будущих сессий.
