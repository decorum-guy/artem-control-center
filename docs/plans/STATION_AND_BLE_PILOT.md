# Пилот Станции Мини 2 и BLE на Samsung

Рабочий список владельца от 23 ноября 2026. Home Assistant остаётся на VPS.
Работа ведётся от `origin/main` в отдельной ветке. Проверка Samsung шла
через `control-panel-pc`, с отдельными процессами на loopback и временными
Python-зависимостями. Основной runtime, HA и сеть не менялись.

| Задача | Условие готовности | Текущий результат |
| --- | --- | --- |
| BLE-лента ELK-BLEDDM | Привязать радиоадрес к своей ленте. Проверить GATT, физические on/off, RGB и яркость. Дать отдельно две кнопки питания. | Выключение и включение с Samsung физически подтверждены в двух соединениях. Напрямую проверены яркость и запись RGB. Подробности ниже. |
| Текущая музыка Станции | Одна авторизованная сессия Samsung → Glagol. Живые метаданные и сохранение управления. | Подтверждены idle, два трека после внешних действий, пауза и повторная сессия. Виджет и сборщик готовы к ревью. |
| Сколько хранится трек | Измерять от остановки того же трека до его явного удаления станцией. Показать длительности в настройках. | Сбор запущен на Samsung. Первый живой замер начался после голосового «стоп». Время до исчезновения пока неизвестно. |
| Нативные напоминания | Подтвердить читающий источник и последовательно проверить создание, перенос и удаление. | Голосовое напоминание было видно в приложении владельца, но отсутствовало в опрошенном API будильников. Читающий адаптер заблокирован отсутствием подтверждённого API напоминаний. |
| Лайк Яндекс Музыки → YouTube Music | Найти наблюдаемый факт лайка, однозначно сопоставить запись, проверить официальный API и пользовательское согласие. | После голосового лайка пользовательская библиотека Яндекса увеличилась на один трек. Записи в Google не проводились. |

## Проверенные среды

- Mac: macOS 26.5.1 (25F80), Node 26.3.0, локальная Python 3.12.14, Chromium
  Playwright. На Mac шли исходный аудит и локальные fixture-проверки V2/V3.
- Samsung: Windows 10, сборка 19045, Python 3.12.10, websockets 15.0.1,
  временный Bleak 3.1.0. Основной runtime на ревизии `2b361918f11b`.
- Станция: владелец подтвердил Мини 2, discovery определил платформу
  `yandexmini_2`. Версию firmware отдельно не записывали.
- iPhone: владелец отключал приложение duoCo Strip и проверял запись в
  «Доме с Алисой». Модель телефона и версии приложений не сверяли.

## Станция

Проверка с Samsung на порте 1961 сверяет SHA-256 сертификата домашней
Станции перед отправкой токена. Подтверждённая авторизация получена через
QR-вход владельца. Реализация сверена с
[YandexStation v3.22.3](https://github.com/AlexxIT/YandexStation/tree/v3.22.3),
коммит `9a18567a59d7`. Обмен авторизованного X-token выдаёт OAuth
Яндекс Музыки. С ним запрос к Quasar выдаёт токен конкретной колонки.
Проба только с Passport cookies упёрлась в `auth_required`. Исправленный
обмен прошёл на Samsung с чистым клиентом. Сборщик запрашивает новый
токен колонки перед переподключением и обновляет OAuth при отказе. При
отозванной авторизации показывает `auth_required`. Временный запуск
доставляет X-token и параметры OAuth через SSH stdin и одноразовый DPAPI
файл пользователя Windows. После чтения файл удаляется, токены остаются
в памяти. Credentials не входят в код, браузер или историю замеров.

В живой проверке Станция без опроса отправляла `state.playerState`.
Тип музыки `Track`, название `title`, исполнитель `subtitle`, URL
`extra.coverURI`, признак воспроизведения `state.playing`. Два трека
с отличающимися идентификаторами пришли после действий владельца вне
клиента. При паузе и голосовом «стоп» сохранён тот же трек с
`playing=false`. До воспроизведения подтверждено пустое состояние.
В [справочнике Яндекса](https://alice.yandex.ru/support/ru/station/skills/audio-settings)
«пауза» и «стоп» объединены. Таймаут очистки в документации не найден.

Секундомер запускался в клиенте при отправке первого сообщения с
токеном. Первое состояние пришло через **156 мс**, при повторном
соединении после закрытия первого — через **203 мс**. В первом соединении
медиана интервала между 90 кадрами составила примерно **1,05 с**,
во втором между 11 кадрами на паузе — **5,0 с**. Это интервалы
наблюдений Mini 2. Действия владельца и кадр браузера не были измерены
общим секундомером, поэтому задержка голоса до отрисовки неизвестна.

Коллектор создаёт одно соединение на процесс. Glagol отправляет новые
состояния, а WebSocket ping проверяет транспорт. Актуальность
проверяется отдельно по последнему распознанному состоянию. При
семантическом изменении обновляется snapshot, при смене одного лишь
прогресса событие не создаётся. Команды и пресеты по-прежнему
обслуживаются прежней интеграцией. Штатный Samsung сообщил 7 из 7
доступных команд, их маршруты и пресеты покрыты тестами Playwright. Обложки ограничены доменами CDN
Яндекса, загружаются по известному пути с лимитом ответа и кэшируются
локально.

Опциональная конфигурация Panel Agent задаётся через
`PANEL_STATION_PLAYBACK_HOST`, `PANEL_STATION_PLAYBACK_CERT_SHA256`,
`PANEL_STATION_PLAYBACK_DEVICE_ID`, `PANEL_STATION_PLAYBACK_X_TOKEN`,
`PANEL_STATION_PLAYBACK_MUSIC_CLIENT_ID`,
`PANEL_STATION_PLAYBACK_MUSIC_CLIENT_SECRET`. Последние три значения
передаются через разрешённый контур секретов. Параметры авторизации
зависят от доступности применимого приложения OAuth и Яндекс Музыки.
Никаких переменных для production в пилоте не выставляли.

### Замер на Samsung

Локальная страница на Samsung — `http://127.0.0.1:8794/`. Она работает
отдельно от панели в течение максимум 168 часов с 23 ноября. При
перезагрузке процесс останавливается, ранее сохранённые наблюдения
остаются. Измерение начинается только после наблюдаемого перехода
того же трека из playing в paused. В расчёт попадает только явно пустое
состояние. Следующий трек, возобновление или потеря сигнала помечаются
отдельно. Прерванный пробный процесс с `auth_required` остановлен.
Сохранённые данные содержат время, длительность и исход замера.
Названия, ID треков и аккаунтов на диск не записываются.

В подготовленной панели история находится в «Настройки → Станция ·
хранение трека после паузы» и появляется с
`PANEL_STATION_RETENTION_ENABLED=true`. До установки панели рабочая
страница для владельца — отдельный пилот. Остановить его можно по PID
после проверки, что командная строка относится к
`station-retention-pilot\start-pilot.pyw` в каталоге пилота. История
изолированного процесса — `retention.json` рядом с его скриптом.

## ELK-BLEDDM

Mac и Samsung обнаружили контроллер после освобождения соединения
duoCo Strip. Он исчез с обоих сканов при обесточивании и вернулся
с тем же адресом на Samsung после подачи питания. Идентификаторы
CoreBluetooth и Windows учитываются отдельно. Профиль
`FFF0 / FFF3 (read, write-without-response) / FFF4 (notify)` совпал с
[elkbledom](https://github.com/dave-code-ruiz/elkbledom/blob/f1b22177cd077dc666f4961a0bafb2b5fd3dc0e7/custom_components/elkbledom/models.json)
на коммите `f1b22177cd07`. Между записями соблюдалась пауза ≥ 350 мс.

| Операция | Ответ программы на Samsung | Физический результат |
| --- | --- | --- |
| Выключить | Запись без ответа GATT завершилась | Погасла, подтверждено владельцем |
| Включить | Запись через новое соединение завершилась | Загорелась, подтверждено владельцем |
| Красный, зелёный, синий | Все три записи приняли два прогона | Владелец сообщил почти мгновенный отклик. Цветовые результаты уточняются по каждому каналу |
| Яркость 20, 65 и 100% | Используется отдельная команда яркости DDM | Владелец увидел изменения |
| 90 → 100 → 80 → 90 → 85 → 90% | Samsung принял все шесть записей по отдельности | Владелец увидел изменения в серии, но не смог уверенно отличить 85% от 90%. Квантование и 0% не проверены |

Повторяемый инструмент `scripts/diagnostics/ble_strip_pilot.py` принимает
`scan`, `inspect`, `on`, `off` и проверенные операции цвета/яркости.
Для запуска установите `bleak==3.1.0` в отдельное окружение Python 3.12+
и укажите `--address` только после проверки снятием питания.
Ни один write не повторяется автоматически. Соединение освобождается после
каждой операции. В отчёт попадает результат API записи, а физический
результат подтверждается отдельно. Состояние через FFF4 не декодировалось.
`scan` выводит и безымянные устройства в локальный терминал.

Второй пилот на Samsung — `http://127.0.0.1:8795/` на два часа,
с кнопками питания, read-only проверкой действующего профиля панели и
отдельным явным разрешением записи в пилот. Нужен Standard или Full.
Loopback, Origin, Host и назначение запроса проверяются. Результат
помечен как «Команда отправлена». Неверные Origin/Host, отсутствие
заголовка намерения и неизвестная команда отклонены на Samsung.
Физические on/off сначала подтверждались через диагностический клиент.

## Нативные напоминания

По [справке Яндекса](https://alice.yandex.ru/support/ru/station/settings/reminder)
нативный список, редактирование и удаление доступны в «Доме с Алисой».
Владелец голосом создал синтетическую запись, увидел её в этом списке
и удалил. Авторизованный read-only тест того же аккаунта и Станции
в `gproxy/get_alarms` вернул HTTP 200 и список будильников, но ни один
из замеров не вернул маркер теста. Этот API проверен как источник
будильников. Синхронизацию времени/удаления в панели проверять пока
не на чем. Нужен подтверждённый интерфейс чтения с ID записи и временем
изменения, после чего можно проверить CRUD-наблюдение отдельным тестом.

[Яндекс Диалоги](https://yandex.ru/dev/dialogs/alice/doc/ru/request)
передают запросы тому навыку, к которому обратился владелец. В панели
уже описан отдельный [маршрут своего навыка](HA_PERSONAL_ASSISTANT_PLAN.md).
Его напоминания видны в Planning, но они имеют другого владельца данных
и не отражают произнесённое напрямую нативное напоминание Алисы.
[alice-notify](https://github.com/SelfHarmony/alice-notify/blob/6b2bb98/src/alice_notify/reminders.py)
создаёт разовое напоминание текстовой командой, повтор — сценарием.
[yandex-station-mcp](https://github.com/yasg1988/yandex-station-mcp/blob/e5ed061/yandex_station_mcp/client.py)
также отправляет текстовую команду для создания. Нативного списка
напоминаний в этих реализациях нет.

## Голосовой лайк и YouTube Music

[Яндекс](https://alice.yandex.ru/support/ru/station/skills/your-playlist.html)
документирует добавление в «Мне нравится» фразой «Лайк». В живой пробе
владелец включил ранее не отмеченный трек, сказал Алисе поставить лайк,
затем читающий запрос к его библиотеке вернул ровно один новый элемент
и ни одного удаления. Сверка проводилась раз в 12 секунд временным
клиентом на Mac. Она подтверждает изменение библиотеки. Причину изменения
и ID текущей композиции следует связать отдельно перед запуском
автоматического переноса. Сам голос и аудио не записывались.

[YouTube Data API](https://developers.google.com/youtube/data/reference/rest/v3/videos/rate)
умеет поставить лайк конкретному videoId с OAuth пользователя.
[Поиск YouTube](https://developers.google.com/youtube/data/reference/rest/v3/search/list)
даёт варианты, но по одному названию случаются клипы, каверы, лайвы и
ремастеры. Для первого практического прогона подходит вариант:
подтвердить найденную запись перед лайком, затем проверить именно
«Понравившаяся музыка» в аккаунте YouTube Music. Для отдельной подборки
есть официальный [API плейлистов](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/insert).
[Правила YouTube](https://developers.google.com/youtube/terms/developer-policies)
требуют явного и конкретного согласия перед автоматическим лайком.
Доступ Google, соответствие записи и появление в «Понравившейся музыке»
живьём не проверялись. Кнопок и фоновой синхронизации в панели пока нет.

## Проверки и откат

`npm run check`, `git diff --check` и Playwright для V2/V3.
Экраны станции на 1280×720 и 720×1280 сняты с тестовой обложкой,
длинным названием и паузой. Наблюдения с реальной Станции проверены
отдельно. Для отката изолированных проб достаточно остановить их процессы.
При будущей установке функции внутри панели для отключения сборщика
убирается его необязательная конфигурация при штатном обновлении.
