## 4. Нативные напоминания: создание через Алису, чтение на Samsung

Нужны обычные напоминания Алисы вида «напомни через десять минут проверить панель». Будильники `get_alarms`, календарь и задачи своего навыка не подтверждают этот результат.

### Самостоятельный эксперимент

Используй существующий HA для отправки Алисе команды создания одной записи с уникальным тестовым маркером. Не проси владельца произнести её. Выбирай время с запасом вне ночного окна испытаний, чтобы успеть проверить и убрать тест без ночного срабатывания.

Проверь создание, затем чтение Samsung, изменение времени и удаление своей записи. Не создавай серию новых напоминаний, пока исход предыдущей операции неизвестен. Удаляй только однозначно опознанные тестовые записи, сохраняя пользовательские.

Для локального чтения на Samsung проверь `sendText` с текстом «Перечисли напоминания» через существующую Glagol-сессию. Для запроса с ответом используй собственный `requestId`; не рассчитывай, что ответ на облачную команду автоматически придёт другому локальному клиенту.

Единственный цикл чтения WebSocket обслуживает музыку и ответы. Ожидание ответа регистрируется до отправки, очищается при ответе/timeout/отмене/разрыве и принадлежит конкретному соединению. Кадр может содержать и ответ, и `playerState`: обрабатывай оба. Ответ без `playerState` не освежает музыку.

Разбери фактический `vinsResponse`, варианты `response`/`payload.response`, весь массив карточек, streaming и текст. Не ограничивайся `cards[0]`.

### Реализация

При воспроизводимом читающем источнике реализуй адаптер Samsung, контракт, обновление и список в обычной панели. Поля: текст, реальное время, часовой пояс, подтверждённая повторяемость, observedAt, freshness и полнота. Отображение — Europe/Moscow.

Отсутствие provider ID не блокирует read-only список. Локальный UI-ключ не является ID провайдера. Одинаковые текст и время не доказывают, что две записи — одна.

Неполный ответ, timeout, streaming и неизвестная схема не означают пустой список. Предыдущий подтверждённый снимок сохраняй с правильной свежестью. Удаление выводится только из нового полного результата.

Проверь, вызывает ли «Перечисли напоминания» речь и влияние на музыку. Говорящий `sendText` не превращай в частый фоновый опрос; до подтверждения тихого способа оставь явное обновление без автоматического повтора. SSE reconnect и фокус вкладки не должны запускать речь.

Если Glagol даёт лишь звук/статус/неполный текст, самостоятельно исследуй доступный авторизованный читающий интерфейс нативного списка для вызова с Samsung. Не придумывай endpoint. Samsung должен выполнять адаптер; возможную зависимость от облака Яндекса укажи честно.

При HTTP 500 сам выясни точный service, media type и безопасный след ошибки. Различай облачный `play_media` и локальный `send_command`. Локальную операцию выполняй через Samsung. Ошибка одного пути не останавливает остальные направления.

## 5. BLE: обычная карточка и восстановление без вмешательства

Реализуй один менеджер подтверждённой ленты в Panel Agent, общий для вкладок. Перенеси работающие команды из диагностики в штатный код.

Нужны последовательные операции, общий lock для команд и probe, ограниченные scan/connect timeout, отмена, освобождение клиента и восстановление после отказа/возобновления Windows.

При потере доступности повторяй попытку подключения примерно через пять секунд после завершения предыдущей. Одновременно выполняется одна попытка. Укажи длительность самой попытки; пятисекундный интервал не означает гарантированное восстановление за пять секунд.

Проверка доступности: подключиться к своей ленте, проверить известный GATT, освободить соединение. Не отправлять power/RGB для проверки связи. Advertising не равен доступному GATT.

Предпочти короткие соединения, чтобы телефон мог пользоваться duoCo Strip. Не отбирай соединение принудительно. Панель должна возвращать возможность новой команды после освобождения контроллера без рестарта.

Повторяй подключение, а не потенциально выполненную команду. После восстановления старые нажатия и цвет не проигрываются. Неопределённая запись остаётся неопределённой; очередь ползунка при разрыве очищается. Перед записью проверяются актуальные gates.

Интегрируй on/off, подтверждённые цвета, яркость и статус связи в обычную карточку ленты. Явно выбери провайдера; исключи конфликт HA- и BLE-сервисов. Существующая HA-карточка требует адаптации к BLE, который не подтверждает физическое состояние.

Раздели `write_completed`, неизвестное состояние устройства, последнее запрошенное значение и время успешной проверки связи. После действия телефона не утверждай прежний цвет Samsung.

### Проверка без телефона владельца

Прогони разрывы до/после записи, автоматическое восстановление и отсутствие replay на управляемом транспорте. Проверь настоящий reconnect на Samsung.

Если BLE Mac доступен, используй его как второй клиент именно подтверждённой ленты: занять соединение, проверить реакцию Samsung, освободить, дождаться автоматического восстановления и выполнить новую команду. CoreBluetooth UUID Mac не подставляй как Windows-адрес.

Такую проверку обозначь как конкуренцию с клиентом Mac. Реальный цикл с duoCo Strip на iPhone остаётся коротким пунктом утренней приёмки, если без владельца его выполнить невозможно. Это не блокирует реализацию и остальные проверки.

Физический цвет/свечение не объявляй подтверждёнными по одному успеху API; используй прежние подтверждения владельца для проверенного протокола и явно обозначь границы новой проверки.
