# Поиск по всему выбранному плейлисту

Фильтр страницы «Музыка» сейчас работает по загруженным строкам. Следующий этап добавит явное действие «Искать по всему плейлисту» для текущего источника. Разрешение на воспроизведение и выбор записи остаются отдельными действиями.

- Начинать с загруженных строк и показывать совпадения по мере того, как backend проходит оставшиеся страницы того же плейлиста. Использовать существующий узкий адаптер продолжений. YouTube Music запрашивать через Happ. Сохранять порядок и повторные позиции.
- Ограничить один активный поиск на источник в Panel Agent, ширину запроса, параллельность, объём кэша и бюджет чтения. Стартовый бюджет для калибровки — 10 страниц или 20 секунд на цикл с возможностью продолжить. Ограничивать частоту запросов по измерениям на Samsung. Пустой запрос поиск не запускает.
- Кэшировать только нормализованные поля поиска и стабильные ссылки на записи. Ключ включает провайдера, подтверждённый аккаунт, ID плейлиста с владельцем, поколение каталога и версию индекса. Ротация credentials того же подтверждённого аккаунта сохраняет строку запроса и позицию. Смена аккаунта очищает данные и отменяет операции.
- Отменять продолжения при смене запроса или списка и по кнопке «Остановить». Запоздалые ответы не меняют текущий экран. Обновление списка инвалидирует старый индекс и старые продолжения; уже видимые совпадения можно пометить как данные предыдущей версии до успешного чтения.
- Пока источник не подтвердил конец списка, показывать «Проверено N позиций» и статус причины остановки. При временной ошибке сохранять найденное и предлагать повторить с сохранённой позиции. «Ничего не найдено» для всего плейлиста допустимо только после подтверждённого окончания чтения.
- Приёмка: совпадение после первой порции и за пределами первоначального бюджета, повторяющиеся строки, изменения списка, переключение аккаунта, отмена, сбой Happ, стабильная прокрутка и отсутствие команд воспроизведения во время поиска. Проверить большие фикстуры и один реальный плейлист каждого источника.
