## Подготовка под пользователем задачи Windows

1. Сверить [карту доступа](../INFRASTRUCTURE_ACCESS.md), [Windows runtime](../WINDOWS_PRODUCTION_RUNTIME.md), [голосовые сценарии и пульт](../TV_ACCESS.md). Установочной машиной остаётся Samsung. Проверить версию установленного Edge, доступность Happ на `127.0.0.1:10809`, существующий приватный HA-маршрут, TV Executor и задачу `Artem Control Center Runtime` с интерактивным входом штатного Windows-пользователя. Updater сам устанавливает версионную Python-среду, в которой на Windows появится Playwright. Команда установки браузеров для этой функции не требуется.
2. Сделать защищённую локальную копию runtime.env, политики доступа, capability overrides, раскладок, видимости устройств, настроек календаря, пользовательских данных/кэшей, истории удержания, текущих vault и маркеров last-known-good. Список фактических путей брать из runtime.env и конфигурации; отдельно учесть checkout-пути, например настроенный `PANEL_OVERVIEW_LAYOUT_PATH`. Planning и напоминания Яндекса обслуживаются существующими внешними источниками. Проверка доступности и сверка данных не требуют изменения или очистки их хранилищ.
3. Основной корень — `%LOCALAPPDATA%\ArtemControlCenter`. На Samsung задача `Artem Control Center Runtime` принадлежит Windows-пользователю `artem-panel`; перед переносом сверить SID интерактивного пользователя с principal задачи. Под этим пользователем создать защищённый `station-credentials`, отключить наследование от родительского каталога и оставить наследуемый Full Control только этому SID и SYSTEM. В runtime.env использовать абсолютные развёрнутые пути. Перенос DPAPI выполняется на том же Samsung под тем же Windows-пользователем. Читаемость проверить без вывода содержимого. Четыре файла переносятся отдельно от браузерного каталога.

| Подключение | Файл в закрытом каталоге | Постоянная переменная |
| --- | --- | --- |
| Station / Яндекс Музыка | `oauth.dpapi` | `PANEL_STATION_PLAYBACK_CREDENTIAL_FILE` |
| Нативные напоминания | `reminders.dpapi` | `PANEL_STATION_REMINDER_CREDENTIAL_FILE` |
| Лайки и подтверждение канала YouTube Data API | `youtube-music.dpapi` | `PANEL_YOUTUBE_MUSIC_CREDENTIAL_FILE` |
| Каталоги, плейлисты и обложки YouTube Music | `youtube-library.dpapi` | `PANEL_YOUTUBE_LIBRARY_CREDENTIAL_FILE` |

## Постоянный профиль YouTube Music

- Источник переноса — только `%LOCALAPPDATA%\ArtemControlCenter\autonomous-2026-11-24\station-credentials\music-edge-profile`. Конечный путь — `%LOCALAPPDATA%\ArtemControlCenter\station-credentials\music-edge-profile`, рядом с постоянным `youtube-library.dpapi`. Kiosk-профиль `edge-profile` расположен отдельно.
- Перед копированием остановить preview по штатному порядку ниже и дождаться закрытия Edge, который использовал именно исходный профиль. Под `artem-panel` подготовить закрытый staging-каталог `station-credentials` с таким же ACL владельца и SYSTEM. Проверить дерево на reparse points. Скопировать только каталог `music-edge-profile`, сохраняя структуру файлов и исключая временные `Singleton*` и `lockfile`. У копии должен наследоваться ACL защищённого назначения. ACL исходных файлов не переносить.
- В staging проверить тем же backend через Happ сверку ожидаемого канала и обычное чтение первой страницы. Проверку восстановления выполнять с отдельной диагностической копией browser vault. Подтвердить неизменность исходных файлов. Если сверка прошла, после решения об установке перенести закрытую проверенную копию на конечный путь. Существующий постоянный профиль, если он обнаружен, сохранить для отката перед заменой.
- Если перенос не подтверждён, первичную авторизацию постоянного профиля провести из настроек `/settings` под штатным процессом через «Подключить YouTube Music». Войти в обычном Edge, выбрать ожидаемый канал и закрыть именно это окно. Панель откроет тот же профиль для фоновой проверки канала и первой страницы. Затем повторить обычное чтение после перезапуска. Копия browser vault сама по себе даёт API-чтение и не создаёт профиль для автоматического восстановления.
- Владелец завершил вход в новый выделенный профиль из кнопки панели в изолированной подготовке на Samsung под SID штатной задачи. После закрытия окна подтверждены ожидаемый канал, запись нового DPAPI vault и 25 позиций каталога. Повторное чтение после перезапуска прошло. Закрытый профиль скопирован в защищённый staging под тем же пользователем. На отдельной копии vault два управляемых 401 вызвали по одному реальному запуску Edge через Happ, заново сверили канал и вернули по 25 позиций обычным чтением за 8,64 и 14,70 с. Для установки использовать эту проверенную пару из preview. Первоначальная копия прежнего профиля требовала входа и для переноса не подходит.
- При откате сохранить текущий закрытый каталог для диагностики, восстановить предыдущий профиль и его vault из пары резервных копий в том же ACL. До завершения проверки не удалять исходный профиль preview.

## Конфигурация выпуска

| Функция | Настройки |
| --- | --- |
| Основной режим | `PANEL_AGENT_MODE=production`. Сохранить утверждённый профиль доступа, общие и узкие write gates, рабочие HA и Alice подключения. |
| Станция | `PANEL_STATION_PLAYBACK_HOST`, `PANEL_STATION_PLAYBACK_CERT_SHA256`, `PANEL_STATION_PLAYBACK_DEVICE_ID`, `PANEL_STATION_PLAYBACK_VOICE_ENTITY` по проверенной конфигурации Mini 2. `PANEL_STATION_RETENTION_ENABLED=true`. |
| Напоминания | Фактические `PANEL_STATION_REMINDER_DEVICE_ID` и `PANEL_STATION_REMINDER_HOME_ID` из проверенного дома и Mini 2. `PANEL_STATION_REMINDER_WRITES_ENABLED=true` для утверждённой записи. |
| Музыка | `PANEL_MUSIC_LIBRARY_ENABLED=true`, `PANEL_YOUTUBE_BROWSER_CONNECT_ENABLED=true`, `PANEL_YOUTUBE_MUSIC_HTTP_PROXY=http://127.0.0.1:10809`, `PANEL_YOUTUBE_MUSIC_ENABLED=true`, `PANEL_YOUTUBE_MUSIC_STATION_ENTITY` с уже проверенной entity. Сохранить `PANEL_ALICE_STATION_ACTIONS_ENABLED`. |
| ТВ и голос | `PANEL_TV_VOICE_ENABLED=true`, `PANEL_TV_VOICE_STATION_ENTITY`, `PANEL_ALICE_VOICE_FEEDBACK_ENABLED=true` и существующий `PANEL_TV_EXECUTOR_TOKEN_FILE`. Сохранить существующие сценарии в Яндексе. |
| Ленты и климат | `PANEL_LIGHT_STRIP_PROVIDER=both`, проверенный `PANEL_BLE_STRIP_ADDRESS` спальни, действующие `PANEL_LIGHT_STRIP_ACTIONS_ENABLED` и `PANEL_HOME_CLIMATE_ACTIONS_ENABLED`. |

Updater устанавливает код и обновляет сборку. Изменения `runtime.env` готовятся и применяются отдельно под защищённым ACL с резервной копией.

## Перенос настроек, истории и выбора ленты

- Источник выбора спальни `%LOCALAPPDATA%\ArtemControlCenter\youtube-login-ux-r376\.cache\device-visibility.json` содержит `bedroom-ble-light-strip`. Рабочий preview на 8797 использует свой файл. Цель брать из актуального `PANEL_DEVICE_VISIBILITY_PATH` или, при его отсутствии, из `.cache/device-visibility.json` рабочего каталога штатной задачи. На 25 ноября основной файл содержал соседний параметр видимости и не содержал `overviewLightStripId`.
- После остановки писателей сохранить основной файл и перечитать его перед применением. Сохранить любой явно заданный основной выбор, включая `null` («Автоматически»). Если ключ отсутствует, применить к копии только `OverviewLightStripPatch` через `DeviceVisibilitySettingsStore` с текущей ревизией. Сверить соседние настройки. Если обнаружены неизвестные поля или оригинал изменился после чтения, остановить замену и сверить данные. При успешной проверке заменить файл атомарно. Обе ленты остаются в «Доме».
- На 25 ноября в источнике истории `autonomous-2026-11-24\profile\ArtemControlCenter\station-retention.json` было 26 валидных завершённых наблюдений. Целевого `station-retention.json` в корне runtime не было. После остановки процессов снова прочитать обе стороны. Проверить по `StationRetention`, объединить строки по `startedAt/endedAt/seconds/outcome` без дублей и оставить до 100 последних. Сохранить интервал, завершённый как `signal_lost`, если он появился при остановке. Активный интервал между процессами не переносится. Сохранить исходные копии.
- Из разрешённой конфигурации preview применять только проверенные значения для ключей подключений из таблицы. Сохранить остальные актуальные настройки владельца. Updater не обновляет `runtime.env`.

## Передача управления и критерии приёмки

1. По отдельной команде владельца принять один итоговый PR против `main`. Перед обновлением сверить чистый Samsung checkout, CI точного кандидата и равенство дерева итогового `origin/main` принятому кандидату, включая workflow. Промежуточные PR со старыми workflow на `main` не устанавливать.
2. Остановить процесс preview через файл `stop` в `%LOCALAPPDATA%\ArtemControlCenter\autonomous-2026-11-24`. Дождаться закрытия 8797, завершения процесса и освобождения BLE. Остановить временные экземпляры подготовки, перечисленные в #375. Удалить задачу `Artem Control Center Music Release Preview` после её остановки. На этом шаге допустима пауза голосовых функций. Основной обработчик запускается только после остановки preview.
3. Остановить 8787 через `scripts/windows/stop-production.ps1 -ForUpdate`. Снять финальные резервные копии и применить порядок переноса истории и видимости выше. Подготовить четыре vault и выделенный браузерный профиль под тем же Windows SID. После проверок заменить профиль и browser vault одной согласованной парой.
4. Применить защищённый runtime.env и запустить штатный `Update Control Center.cmd` из чистого `main`. Чистота предохраняет от отката поверх чужих изменений. Проверить `/health/ready`, точный SHA в `http://127.0.0.1:8787/api/v1/system/production-build`, состояние задачи `Artem Control Center Runtime`, единственный обслуживающий процесс, единственного получателя голосовых событий и единственного BLE-менеджера. Изолированный 8797 должен оставаться закрытым.
5. С Samsung проверить `/music` в киоске, Яндекс-плейлисты, YouTube-каталог и догрузку, ожидаемый канал OAuth без нового лайка, тихое чтение напоминаний, историю, существующие Planning/раскладки, два виджета лент и климат. Проверить одно подтверждённое действие ТВ и короткое «Сохраняю» на уже понравившемся треке, с одним получателем. Проверить автозапуск при согласованном цикле входа Windows. Повторить чтение через локальный Samsung после отключения диагностического клиента Mac. HA, внешний пульт и Happ должны продолжать работать по существующей схеме.

Если штатный updater остановится на ошибке, проверить его автоматический откат версии и readiness. Для регрессии после установки отключить новый обработчик или остановить runtime через `scripts/windows/stop-production.ps1 -ForUpdate`, восстановить резервную копию `runtime.env` и `2b361918f11ba2ae40805fa65bcdbe1b3f6f99d8` (если перед установкой last-known-good подтверждён на этом SHA) по [штатному сценарию](../WINDOWS_PRODUCTION_RUNTIME.md#update-and-automatic-rollback), собрать зависимости и production-профиль, запустить `scripts/windows/start-production.ps1` и сверить ревизию на 8787. Перед восстановлением данных сохранить новые записи и историю. Возвращать резервные данные только при необходимости. Preview можно возобновить только при подтверждённом выключении соответствующих обработчиков в основном процессе. Отключение одного browser helper — `PANEL_YOUTUBE_BROWSER_CONNECT_ENABLED=false` и штатный перезапуск. Существующий vault и официальный OAuth сохраняются.

## Результаты на Samsung, 24 ноября 2026

- В preview кнопка настроек открыла обычное окно установленного Edge через Happ. За 9,26 с канал совпал с ожидаемым, первая страница каталога прошла проверку, DPAPI-файл заменился. Вторая вкладка получила 409, процессы окна завершились. Выделенный профиль для пробы подготовлен из ранее разрешённой сессии. Полный новый вход с паролем и 2FA в этом прогоне не выполнялся.
- Подстановка заведомо недействительной сессии только в preview дала 401. Автоматическое восстановление из того же профиля прошло за 9,58 с. Каталог и курсор второй порции остались действующими, старые ключи запуска изменились. При последующей отмене защищённый файл не изменился. Для временной ошибки транспорта или неизвестной схемы тесты подтверждают отсутствие автоматического запуска Edge.
- Прочитаны 41 позиция каталога, две порции понравившихся по 100 и обычный плейлист из 20. Открытый UI на 1280×720 и 720×1280 показал по две реальные обложки. Подменённый 503 каталога сохранил выбор, список и позицию 6400 px, живой запрос восстановил каталог. После перехода в другой раздел позиция восстановилась. Браузерная регрессия проверяет сохранение фильтра и второй порции при ротации и перезапуске, а также сброс просмотра при другом канале. После перезапуска самого preview прочитаны 41 позиция и прежние 19 замеров Станции.
- Во время подключения замерены 9 процессов окна и драйвера, суммарный working set 902,9 МиБ и 11,06 CPU-секунды к моменту замера. Working set процессов включает общие страницы. В покое до и после попытки этих процессов не было.
- Официальный OAuth выдал новый access token на 3599 с, проверка канала в Data API прошла. Ограниченная попытка прочитать InnerTube с этим access token через Happ дала HTTP 400 на `account/account_menu`. Параметр срока refresh token отсутствовал в ответе. Текущий режим проекта в Google Cloud Console не подтверждён; срок refresh token остаётся неизвестен. OAuth и настройки проекта не менялись.
- Локально прошли `npm run check`, production build и smoke с Python 3.12, 14 сценариев Playwright Music, Climate и настроек. Первый smoke выбрал системный Python 3.9 и остановился на существующей аннотации Pydantic; повтор со средой 3.12 прошёл. [Проверки итогового PR #375](https://github.com/decorum-guy/artem-control-center/pull/375/checks).
