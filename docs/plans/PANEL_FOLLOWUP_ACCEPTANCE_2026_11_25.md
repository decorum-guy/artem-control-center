## R1. Пауза/остановка во время подбора следующего трека

**Приоритет до выпуска очереди. Вывод из control flow, не воспроизведение на Samsung.**

В [music_library.py](https://github.com/decorum-guy/artem-control-center/blob/b0314a7c82474300f45fe0b617fcb0e8f81151ad/apps/panel-agent/src/panel_agent/music_library.py) _play_playlist_position переводит очередь в working и ждёт страницу либо _find. В этом состоянии navigate_playlist возвращает None для pause, не отменяя продолжение. [StationActionExecutor](https://github.com/decorum-guy/artem-control-center/blob/b0314a7c82474300f45fe0b617fcb0e8f81151ad/apps/panel-agent/src/panel_agent/station_actions.py) затем отправляет обычную локальную паузу. _observe_playlist игнорирует события, пока status не playing.

Поздний результат может пройти _playlist_allowed и отправить play_track: права и поколения источников проверяются, отмена намерения воспроизведения — нет. Отдельная остановка возвращает busy при занятом play_lock; UI не показывает её при working.

Исправление: отмена/пауза должны инвалидировать ожидающее воспроизведение до ожидания сетевого lock. Начатое чтение может завершиться, но его устаревший результат не должен запускать трек. Не отменять только HTTP await без контроля результата. Сохранить проверки прав и защиту от повторной отправки.

Проверки без Samsung: задержанный _find или чтение страницы → pause/stop → завершение чтения → **ноль последующих play_track**; внешняя остановка/смена трека; явный новый запуск создаёт новое намерение и не блокируется навсегда. UI позволяет отменить working-очередь. После возвращения доступа — один адресный живой прогон.

## R2. Полный поиск после обновления списка

**Вывод из frontend/backend control flow.**

В [MusicPage.tsx](https://github.com/decorum-guy/artem-control-center/blob/b0314a7c82474300f45fe0b617fcb0e8f81151ad/apps/dashboard/src/features/music/MusicPage.tsx) retry обновляет tracks, но не сбрасывает scan. Очистка scan зависит от selected/generation/sessionRevision/query, не от refresh выбранного списка. Backend помечает job playlist_changed, однако завершённый поиск больше не читает этот статус. Старые результаты продолжают сопровождаться надписью «Плейлист проверен полностью».

При обновлении списка отменить старую операцию или явно пометить результат устаревшим. Не показывать complete для новой версии. Проверить завершённый и приостановленный поиск, refresh, отсутствие позднего возврата старого complete; сохранить выбор и разумное положение списка.

## R3. Изменение времени уже начавшейся серии

**Вывод из формы и валидации; поведение native API после исправления ещё нужно подтвердить.**

[AliceRemindersSection.tsx](https://github.com/decorum-guy/artem-control-center/blob/b0314a7c82474300f45fe0b617fcb0e8f81151ad/apps/dashboard/src/AliceRemindersSection.tsx) заполняет дату повторяющейся записи из seriesStartAt. Если начало в прошлом и пользователь меняет время, [station_reminders.py](https://github.com/decorum-guy/artem-control-center/blob/b0314a7c82474300f45fe0b617fcb0e8f81151ad/apps/panel-agent/src/panel_agent/station_reminders.py) передаёт этот datetime в _due_time, который всегда требует будущее, и возвращает time_must_be_future.

Разделить валидацию срока одноразовой записи и anchor повторяющейся серии. Не переносить начало существующей серии автоматически на сегодня. Сохранить проверенную семантику recurrence и readback правила/часового пояса/неизменённых полей. Если поддержанный API не позволяет нужную операцию, обозначить конкретное ограничение.

Проверки: daily/weekly с прошлым DTSTART → изменение только времени; title-only сохраняет расписание; одноразовая запись по-прежнему требует будущий срок; изменение серии не выдаётся за правку одного вхождения.

## Изоляция следующего preview

По отчёту, первый тест темы записал day в основную панель, после чего rose/night восстановлены. Причинная цепочка эпизода по имеющимся данным не установлена.

Подтверждённый механизм риска: [appearance.py](https://github.com/decorum-guy/artem-control-center/blob/b0314a7c82474300f45fe0b617fcb0e8f81151ad/apps/panel-agent/src/panel_agent/appearance.py) использует LOCALAPPDATA/ArtemControlCenter/appearance.json независимо от порта. Разные порты сами по себе не изолируют настройки. Штатный read_only gate запрещает PATCH оформления.

До нового переключения темы проверить отдельный корень настроек preview, фактический appearance.json и origin запросов. Не ограничиваться отдельным Overview layout path. Для проверки изоляции использовать временные каталоги и управляемые данные; на Samsung затем сверить неизменность основного файла и rose/night.
