## Голосовая яркость

Подготовлены фиксированный HA service/event contract, обработчик Samsung,
фактический WMI readback и пример экспорта устройства **Панель** через Yandex
Smart Home. Используются существующее HA WebSocket-соединение, системный
контроллер яркости и обычные access/write gates. Значение — целый процент
0–100; произвольных shell-команд и публичного адреса Panel Agent нет.

HA ждёт подтверждение совпадающего `request_id`; занятость, устаревшее состояние,
тайм-аут и несовпавший readback не превращаются в успех. Подписка на ответ
создаётся до отправки команды. Периодическое наблюдение отражает и ручные
изменения яркости. Ошибка необязательного обработчика не останавливает остальные
HA-функции.

В прежней документации Yandex Smart Home не был установлен. Его актуальное
наличие нужно проверить на VPS; экспорт устройства и привязка аккаунта —
первоначальная настройка. Распознавание фраз «поставь яркость панели 10 процентов»,
«поставь яркость панели 10» и «яркость панели 10» физической колонкой ещё не
проверено. Исходники не являются доказательством голосовой приёмки.

Установка, проверка и отключение: [ALICE_PANEL_BRIGHTNESS.md](../ALICE_PANEL_BRIGHTNESS.md).

## Автоматические обновления

Координатор выбирает текущий `main` разрешённого репозитория и проверяет последние
push-runs всех обязательных workflows и их jobs для **этого же SHA**. Повторная
попытка, другой SHA/branch, skipped, failure или ошибка API оставляют обновление
в ожидании. Перед исполнением ветка проверяется повторно.

VPS принимает подписанный webhook и дополнительно сверяется раз в минуту.
Samsung выполняет исходящую сверку из отдельной задачи Windows; входящего
порта на панели нет. Webhook только будит проверку, не задаёт программу или SHA
для исполнения. Пропущенное событие и временное отсутствие сети покрываются
повторной сверкой.

Состояние и блокировка хранятся вне checkout. Повторный запуск не создаёт вторую
установку, новый push не прерывает текущую. Неопределённый исход после возможной
мутации останавливает все цели этого хоста до проверки оператора. Остановка
worker даёт завершиться текущей транзакции и не запускает следующую цель.

| Цель | Подготовленный исполнитель | Подтверждение результата |
| --- | --- | --- |
| Samsung | Обёртка существующего production updater с точными current/target SHA | Request-bound terminal state, свободный maintenance lease, readiness и фактически обслуживаемая ревизия |
| Telegram-бот | Сборка из точного SHA, адресное обновление контейнера, A8 backup/verify | Image identity/revision label, приватные listeners и health; откат к прежнему образу |
| Home Assistant | Явный список файлов package/component; необязательный официальный image digest | Проверка конфигурации, hashes, API и наличие ожидаемых сущностей; материал для отката |

Home Assistant не объявлен целиком принадлежащим репозиторию бота. Неизменившиеся
управляемые файлы и image pin не вызывают его перезапуск. Смена образа требует
подтверждённого SQLite recorder и согласованной полной копии остановленного HA;
неизвестная внешняя БД не обновляется автоматически.

Для main-push CI бота опубликован отдельный
[AliceTG_Bot PR #45](https://github.com/decorum-guy/AliceTG_Bot/pull/45), head
`efe9231312c262fa1d8439a84c5581ddb90f2ade`. Его job `validate` прошёл на этом SHA,
[run 45911549576](https://github.com/decorum-guy/AliceTG_Bot/actions/runs/45911549576).
GitHub подтвердил отсутствие загруженных артефактов. Merge не выполнялся.

  `git diff --check` прошли.
- Windows CI запускает 12 проверок adapter: terminal-state decisions, настоящий
  вызов системного Python из PowerShell и разрешение путей реального adapter,
  перенесённого за пределы checkout. Локального PowerShell в Linux-среде нет.
  Итог Windows/GitHub CI относится к точному head PR и указан в его checks/body;
  наличие теста в workflow само по себе не означает его успешное выполнение.

## Что остаётся на хостах

1. Принять код и отдельно выполнить первоначальную установку на Samsung/VPS.
   Сверить реальный checkout, Windows-пользователя, Compose paths, runtime,
   backup и rollback. Шаблоны не содержат выдуманных действующих путей.
2. Для яркости установить/проверить Yandex Smart Home, добавить HA package и
   компонент, экспортировать только «Панель», включить флаг Samsung. Проверить
   три фразы, фактические проценты и отказ при недоступности.
3. Для обновлений установить стабильные копии worker/adapter, защищённые
   конфигурации/read token, Windows task, VPS unit и точный webhook route.
   По умолчанию все цели выключены; включение выполняется после сверки хоста.
4. Согласовать владельца HA image pin с существующей ручной командой
   `home-maintenance update-ha`, которая использует один Compose overlay.
   Ручной путь должен сохранять тот же pin либо не выполнять конфликтующее
   обновление плавающего образа. Определить фактический recorder до image update.
5. На принятом выпуске подтвердить установку без Mac, реальный served SHA,
   health, повторный webhook и восстановление после offline. Отказ/rollback
   проверять в изолированном контуре, не создавая неисправный production выпуск.

После этой первоначальной настройки обычные новые зелёные main устанавливаются
без поручения локальному агенту. Изменение самого deployment worker, его CI
policy или путей остаётся явной операцией обновления установленного bootstrap.
Это не связано с необходимостью вручную запускать каждое обновление панели.

Основная инструкция: [AUTOMATIC_DEPLOYMENT.md](../AUTOMATIC_DEPLOYMENT.md).
