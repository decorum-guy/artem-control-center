# Четвёртый раунд PR #374

## Наблюдения на Samsung

До правки сохранённая браузерная сессия через Happ получила HTTP 200 с JSON от `account/account_menu`. В меню отсутствовал `activeAccountHeaderRenderer`, а в `GFEEDBACK` стояло `logged_in=0`. Исходный `get_account_info()` из ytmusicapi 1.12.4 завершился `KeyError` на ожидаемом заголовке. До чтения каталога штатная операция не доходила. Отдельный запрос каталога вернул ответ с тем же признаком с предложением войти, без grid.

Изолированный Edge на том же Samsung с сохранённой сессией через Happ сначала попал на страницу выбора cookies. После отказа от необязательных cookies в этом профиле YouTube Music открылся и сообщил `LOGGED_IN=false`. Self-check официального OAuth прошёл по тому же Happ. Поведение указывает на потерю браузерной авторизации. Причина, по которой YouTube перестал признавать сохранённую сессию, неизвестна.

На Mac существующая вкладка Music по-прежнему показывала 100 строк, но DevTools недоступен из-за блокировки Mac. Свежего запроса в буфере обмена не было. В обычном Edge на Samsung не найдено действующей сессии YouTube. Для её безопасного восстановления нужен разблокированный Mac и доступ к сетевой панели уже авторизованного браузера. Следующий захват надо проверить по идентичности канала прежде, чем обновлять защищённое хранилище.

## Исправление

Проверка принимает только handle из `activeAccountHeaderRenderer` и сравнивает его с каналом официального OAuth. Имя и фотография не нужны. Явная потеря входа и несовпадение канала требуют авторизации, неизвестная форма меню возвращает ошибку источника. Диагностика разделяет создание клиента, меню аккаунта, первые страницы и продолжения каталога и треков. В журнал попадают только HTTP status, разрешённая категория Content-Type, длительность, объём прочитанных байтов, фиксированные категории ошибок, известные контейнеры, числа и boolean совпадения аккаунта.

Для настоящего пустого каталога требуется распознанный пустой grid. Создание плейлиста определяется по служебному endpoint. Произвольная карточка сообщения, неизвестная строка grid и некорректное продолжение завершают чтение ошибкой. Успешный результат только с `LM` допустим после проверки контейнера и строк. Ошибка обновления оставляет прежний каталог, выбранный список и позицию. Статус остаётся недоступным и после успешного чтения треков до восстановления каталога.

## Проверки

Preview `ab3f5e1` на порту 8797 до 26 ноября 17:13:28 МСК. При первом запросе он вернул `401 auth_required` примерно за 0,77 с. Первичный ответ `account/account_menu` пришёл через Happ за 0,66 с с HTTP 200 JSON и явным `logged_in=0`. Через 124 секунды запрос снова завершился `auth_required` за 0,61 с, а после отдельного перезапуска preview — за 0,89 с. Успешной сверки не было, поэтому эти интервалы не проверяют истечение живого кэша. Синтетические тесты подтверждают повторную проверку аккаунта по истечении 120 секунд и после создания нового экземпляра. Для живой положительной проверки TTL нужны действующая браузерная сессия и первый успешно сверенный аккаунт.

На Samsung настоящая страница показала «Нужно подключить аккаунт». В отдельных прогонах с тестовыми HTTP-ответами в 1280×720 и 720×1280 обычный плейлист показал 12 треков, а `LM` — две порции по 100. Искусственный отказ обновления не сбросил выбранный плейлист, список или прокрутку (6400 px), а повторный запрос восстановил каталог. Переход в «Обзор» и обратно восстановил позицию. Личный каталог, реальные обложки и continuation после новой авторизации ожидают живой проверки.

Прошли `npm run check` (524 JS-теста и 1345 Python-тестов), production build и 11 Playwright-сценариев Music/Climate. Регрессии покрывают старые R1–R5, неизвестные формы каталога, явный выход из аккаунта, несовпадение канала, редирект согласия, транспорт, сбой обновления, восстановление и продолжения.
